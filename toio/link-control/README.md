# 🕹️ toio リンクコントロール (`/toio/link-control/`)

toio コアキューブを **2 台** つなぎ、片方を手に持つ **コントローラ**、もう片方を **操作対象** にして走らせるページ。
コントローラを傾けたり回したりすると、その姿勢に操作対象が追従する。
[コントロールパネル](../control/) と同じくライブラリ非依存・ビルド不要の素の HTML/CSS/JS で、
BLE ラッパー (`../shared/toio.js`) と土台の CSS (`../shared/base.css`) は 2 ページで共有している。

## 操作

| コントローラの動き | 操作対象 |
|---|---|
| **ヨー**（水平に回す） | その向きに追従して回る。回した角度がそのまま目標の向きになる |
| **ピッチ**（前後に傾ける） | 前に傾けると前進、後ろに傾けると後退。倒した角度で速度が無段階に変わる |
| **ロール**（左右に傾ける） | いまは未使用（拡張できるようにしてある。下の「ロールの拡張」を参照） |

1. 「コントローラ」「操作対象」をそれぞれ接続する（役割は `⇄` で入れ替えられる）
2. コントローラを持ちたい向き・角度に構えて **走行開始**（その瞬間の姿勢が「まっすぐ・停止」になる）
3. 傾けて走らせる。**Space** / **Esc** / 画面右上の **停止** でいつでも止まる

途中で構え直したくなったら **いまの姿勢を基準にする** を押せば、その姿勢が中立に取り直される。

## 画面

- **操縦** … 水準器（人工水平儀・方位盤・スロットル）と、いま出している指令（前後 / 旋回 / 追従の誤差 / 左右のモーター値）
- **コントローラの姿勢** … 実機と連動する 3D モデル。ドラッグで視点を回せる。
  床のリングには **青＝目標の向き**、**緑＝操作対象の実測の向き** が出る
- **操作対象の軌跡** … 走った跡を二次元で描く。マットがあれば位置ID、無ければ推測航法
- **ステータス** … 2 台ぶんの接続・電池・ボタン・姿勢角・位置ID・モーター速度・BLEプロトコルバージョン
- **設定** … 追従 / 前後 / 安全・応答 / 通知 / 軌跡 / 表示（内容は下記）
- **通信ログ** … 送受信のバイト列とデコード結果

## 向きの追従のしくみ

コントローラのヨー角の**変化**を目標の向きにして、操作対象の**実測の向き**との差を
旋回速度に変える（PD 制御）。

```
目標の向き = 基準の向き + (いまのヨー − 基準のヨー) × 追従比
誤差       = 目標の向き − 実測の向き          … ±180° に畳む
旋回       = P × 誤差 + D × 誤差の変化率      … 最大旋回速度で頭打ち
左 = 前後 + 旋回 / 右 = 前後 − 旋回           … 115 を超えたら比を保って縮める
```

実測の向きは次の順に探す（設定で固定もできる）。

1. **位置ID** … マットの上にいるときだけ取れる。いちばん正確
2. **操作対象の姿勢角（ヨー）** … マット無しでも取れる。ファームウェア 2.3.0 以降が必要
3. **推測航法** … モーターへの指示から積算する。誤差はたまるが必ず取れる

どれも取れないとき（「追従なし」を選んだときも）は **開ループ**に落ちる。
ヨーの差をそのまま旋回速度にするので、傾けた量だけ回り続ける操作感になる。

取得元が切り替わった瞬間は角度の基準がずれるため、**その時点を中立として取り直す**。
マットから外れて推測航法に落ちても、いきなり回り出さない。

## 安全のための決まりごと

- **姿勢角が途切れたら止める**（既定 800ms）。BLE が切れかけたまま走り続けないようにする
- **切断・ページから離れる・役割の入れ替え**でも止める
- 「止めるべき状態」のときも **0 を送り続ける**。送るのをやめるだけだと、
  キューブは直前の速度のまま走り続けてしまう
- **デッドマン**（コントローラのボタンを押している間だけ走る）を任意で有効にできる
- 左右のモーター値は「実際に送っている値」だけを表示する。走っていないのに数字が出ていると紛らわしいため
- ヨーの符号が逆だと追従が発散する。指示した旋回と実測の向きの変化を突き合わせ、
  逆相関が続いたら「ヨーを反転」を促すメッセージを出す

## 設定

| タブ | 内容 |
|---|---|
| 追従（ヨー） | 向きの取得元、追従比、P / D ゲイン、最大旋回速度、不感帯、開ループ時のゲイン、コントローラ側・操作対象側それぞれのヨー反転 |
| 前後（ピッチ） | 最大速度、全速になる角度、不感帯、反応カーブ（expo）、前後反転、基準にピッチを含めるか |
| 安全・応答 | 送信間隔、加速のなまし、姿勢角が途切れたときの停止時間、効果音、役割ごとのランプ |
| 通知 | 姿勢角の形式 / 間隔 / 条件、ID通知の間隔 / 条件、モーター速度情報 |
| 軌跡 | 軌跡の点数、推測航法の速度係数と輪距 |
| 表示 | 視点の方位・高さ・大きさ、3D のロール / ピッチ反転、既定値に戻す |

設定は `localStorage`（キー `toio-link-control`）に自動保存され、次に開いたときに復元される。

## IMU の符号について

姿勢角の各軸の符号がどちら向きなのかは BLE 仕様に明記がない。個体やファームウェアで
読み替えが要る可能性があるため、次を設定で反転できるようにしてある。

- **コントローラのヨー**（追従の向きに効く。3D モデルの向きにも連動する）
- **操作対象のヨー**（実測の向きに効く）
- **3D のロール / ピッチ**（表示だけ。制御には影響しない）

「前後を反転」はラジコンの設定と同じ**好みの問題**なので、IMU の符号とは別扱いにしている。

## ロールの拡張

ロールは現在なにもしていないが、割り当てを足せるように `app.js` に口だけ用意してある。

```js
const ROLL_ACTIONS = {
  none: function () { /* 未使用 */ },
  // 例: ロールで最大速度を可変にする
  // speedLimit: ({ roll, cmd }) => { cmd.fwd *= 1 - Math.min(0.8, Math.abs(roll) / 60); },
};
let rollAction = 'none';
```

`ctx.cmd` は制御ループが組み立てた指令そのものなので、`cmd.fwd` / `cmd.turn` を
書き換えれば左右のモーター値に反映される。切り替え UI が要るときは、
設定の「表示」タブあたりに `<select data-setting>` を足して `rollAction` に結べばよい。

## 動作条件

- **Chrome / Edge / Opera**（Windows・macOS・Linux・ChromeOS・Android）。Safari と Firefox は Web Bluetooth 非対応
- **iOS / iPadOS** は標準 Safari では動かない。Bluefy などの Web Bluetooth 対応ブラウザアプリが必要
- **HTTPS または localhost** から開くこと
- **姿勢角検出に対応したファームウェア**（BLEプロトコルバージョン 2.3.0 以降）が
  少なくともコントローラ側に必要。ステータス欄で確認できる

## 実装メモ

- **`style.css` / `app.js` / 共有ファイルを変更したら、`index.html` の `?v=` を必ず上げる**
- 送信は `setTimeout` の自己再スケジュールで回している。設定の送信間隔を変えると次の周期から効く
- モーターへの書き込みは `toio.js` 側で `key: 'motor'` にまとめられ、
  未送信の指示は新しいものに上書きされる。BLE が詰まって遅れて効くのを防ぐため
- ヨーは 180/−180 をまたぐので、差分を積算した連続値として持っている。
  追従比を掛けるには畳んだ値ではなく連続値が要る
- 3D は外部ライブラリなしの自前描画。姿勢を 3×3 行列（ZYX オイラー）で作り、
  面ごとに法線を回して裏面を落とし、深さ順に塗っている
- 描画は `requestAnimationFrame`、状態表示は 200ms 間隔。制御ループとは分けてある
