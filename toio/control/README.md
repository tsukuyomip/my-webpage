# 🎮 toio コントロールパネル (`/toio/control/`)

Web Bluetooth API を直接使って、**toio コアキューブの BLE 機能をひととおり** 操作・観測するための
コントロールパネル。ライブラリ非依存・ビルド不要の素の HTML/CSS/JS で、GitHub Pages にそのまま置ける。

## なぜ自前実装か

ブラウザから toio を触るライブラリとしては `p5.toio` があるが、
姿勢角検出・磁力検出・連続点灯シナリオ・音量指定・再生停止・加速度指定モーター制御・
各種しきい値設定などが未実装または固定値で、「toio にできること全部」には届かない。
このツールは公式の
[BLE 通信仕様](https://toio.github.io/toio-spec/)
にあるキャラクタリスティックを直接叩いている。

## 動作条件

- **Chrome / Edge / Opera**（Windows・macOS・Linux・ChromeOS・Android）。Safari と Firefox は Web Bluetooth 非対応
- **iOS / iPadOS** は標準 Safari では動かない。Bluefy などの Web Bluetooth 対応ブラウザアプリが必要
- **HTTPS または localhost** から開くこと（GitHub Pages はそのまま条件を満たす）
- 接続は必ずユーザー操作（ボタン押下）から始まる仕様のため、自動接続はできない

## toio 側の制約（ツールの問題ではないもの）

- **押している長さで鳴らす仕組みは無い**。BLE 仕様にあるのは「長さを指定して鳴らす」だけなので、
  鍵盤では最長 2550ms を繰り返し 255 回ぶん予約しておき、離したときに停止コマンド(0x01)で止めている。
  10 分以上押しっぱなしにすると理屈のうえでは音が切れるが、実用上は問題にならない
- **同時発音はできない**。キューブは 1 音しか鳴らせないので、鍵盤は押した順を覚えておき、
  いちばん最後に押した音を鳴らす（last-note priority）。鳴っていない指を離しても何も起きず、
  鳴っている音を離したときだけ、まだ押されている音に戻すか停止する
- **音は半音単位**。スピーカーは MIDI ノート番号 0〜128（128 は無音）と効果音11種のみで、
  周波数を Hz で指定する・波形を送るといったことは BLE 仕様に存在しない。
  無段階の音が要るなら、キューブをセンサーとして使い Web Audio 側で鳴らすことになる
- **磁気センサー・姿勢角検出は対応ファームウェアが必要**（BLEプロトコルバージョン 2.3.0 以降）。
  古いキューブでは設定を書いても通知が来ない。パネル右上の「BLEプロトコル」欄で確認できる
- 磁力検出を使うには、キューブに磁石が装着されていなくても設定自体は可能だが、
  「磁石の状態」と「磁力」は排他で、どちらか一方しか通知されない

## MIDI の音量

BLE 仕様の MIDI コマンド（0x03）は **1 音につき `[長さ, 音番号, 音量]` の 3 バイト**を送る。
つまり音量は曲全体ではなく**音ごと**に決まる。

- パネル上部の**音量スライダー**は、効果音・鍵盤・**これから追加する音**に使う値
- シーケンスに並べた音は、各行の**「音量 0-255」**で個別に決まる
- **音量を全音に適用** … 並べた音すべてをスライダーの値にする。
  スライダーは既存の音には遡って効かないので、その差を埋めるためのもの
- **フェードイン / アウト** … 前半で上げて後半で下げる山なりにする。
  両端が 0 だと聞こえないので下限を 15% 残してある

数値の入力欄が並ぶだけでは何の値か分からないので、各欄に単位つきの見出しを添えている。

## MIDIファイルの読み込み

標準MIDIファイル（SMF）を `.mid` のまま読める。パーサは
[`../shared/midi.js`](../shared/midi.js) に切り出してあり、ライブラリは使っていない。

### 読むもの

- フォーマット 0 / 1、可変長デルタタイム、**ランニングステータス**（ステータスバイトの省略）
- テンポメタイベント（0x51）。**全トラックから集めて tick 順に並べ**、区間ごとに ms へ直す。
  format 1 だとテンポは 1 本目にしか無いことが多いが、効くのは曲全体のため
- ノートオン／オフ。**強さ 0 のノートオンはオフ**として扱う。
  同じ音が鳴りっぱなしのまま再度来たら、そこで一度切る
- トラック名（0x03）。無ければ「トラック N」

SMPTE 形式のタイムコードには未対応（分解能の最上位ビットが立っているもの）。エラーにする。

### toio に合わせて潰すところ

キューブ側の制約が強いので、そこへ寄せる工程が本体になる。

- **同時に 1 音しか鳴らせない** → 重なった音は**高いほうを残す**。たいていそれが主旋律。
  途中から高い音が入ってきたら、前の音をそこで切って乗り換える
- **休符が要る** → 音の切れ目が 30ms 以上空いたら、無音（音番号 128）を挟んで間を埋める
- **長さは 10〜2550ms の 10ms 単位** → 丸める。5ms 未満は打ち込みの残骸とみなして落とし、
  それ以上で 10ms に満たないものは下限へ持ち上げる
- **1 コマンド 59 音まで** → 59 音ずつに割り、鳴り終わる 60ms 手前で次を送って繋ぐ。
  BLE の往復ぶんの間を見込んだ値。厳密な連続ではないので、速い曲では継ぎ目が分かることがある
- **音量は 0〜255** → MIDI の強さ（0〜127）を、音量スライダーの値を上限として写す

### 操作

- **トラック** … 音の入っているものだけ並ぶ。**いちばん音数の多いもの**を既定で選ぶ
- **移調** … 半音単位。移調した結果 0〜127 を外れた音は捨てる（無理に丸めると音痴になるため）
- **速さ** … %。200 なら倍速
- **先頭59音をシーケンスへ** … 下のシーケンス編集に入れる。手で直したいとき用
- **通しで再生** … 59 音ずつ繋いで最後まで鳴らす。**停止**で途中で止められる

## 姿勢の表示

- **水準器**は人工水平儀（ロールとピッチ）とヨーの向き。人工水平儀には
  10 度ごとのピッチ目盛りと、画面に固定した機体マークを描いてあり、
  これを基準に地平線がどれだけ傾いたかを読む
- **3D ビューワー**は[リンクコントロール](../link-control/)から移植したもの。
  キャンバスをドラッグすると視点が回り、スライダーで向き・見下ろし角・大きさを変えられる。
  床のグリッドと機体固定の軸は個別に消せる
- どちらも姿勢角の通知が要る。センサーのパネルで「適用」するか、軌跡を推測航法にすると有効になる

## ミニマップ

読み取りセンサーのパネルの「ミニマップ」から、軌跡を画面に浮かせて表示できる。
操作しながら軌跡を見たいときのためのもので、パネル本体と同じ内容（位置ID／推測航法の
どちらでも）を、目盛りやキューブ名を省いて小さく描く。

- 読めている位置IDが選択中のマットの範囲外にあるときは、地図の上に座標つきで知らせる。
  範囲外だとキューブの矢印がキャンバスの外に描かれてしまい、「読めていない」ようにしか
  見えないため。市販以外のマット（自分で印刷したものなど）では**自動（実測範囲）**を使う
- 掴んでドラッグすれば好きな位置に置ける。画面外には出ないよう内側に留める
- `⌖` で**姿勢角の水準器**（人工水平儀＋ヨーの向き）を地図の**左に縦並び**で足す。
  地図は正方形のまま、幅の 34% を水準器が使う。オンにすると姿勢角の通知も有効にする
- `⟲` でリセット（原点・0°）。座標と向きをまとめて戻し、軌跡も消す。
  ヨーの基準も取り直すので、実機を好きな方向に置いてから押せばそこが 0° になる
- `⤢` で大きさを 3 段階（140 / 180 / 240px）に切り替え、`✕` で閉じる
- 後ろのコンテンツを塞がないよう、既定ではパネルの背景が半透明（ぼかし付き）で、キャンバス自体は
  塗らずに描いた線だけが見える。さらに **3 秒触らないと薄くなり**、触ると濃さが戻る
- `◐` で半透明を切ると、背景を塗って自動で薄くもしなくなる。軌跡を見続けたいときはこちら
- 表示・位置・大きさは localStorage に覚えるので、開き直しても同じ場所に出る
- 本体とミニマップは同じ描画関数を使い、`compact` の有無だけを変えている

## プログラミングマットの範囲

印刷して使う「toio プログラミングマット」（A3 全面・1200dpi）は市販マットの一覧に無いので、
外周をなぞらせて**到達した座標の軌跡から実測**した。

- 実測範囲 … `11668-11898` / `15929-16096`（1 マス ≒ 1.36mm）
- プリセットはそこから**各辺 5% 内側**の `11680-11886` / `15937-16088`

端をタップしたときに実際のマットから出てしまうのを防ぐための余裕。`inset()` で
実測値から計算しているので、実測値のほうはソースに残してある。割合を変えたいときは
第 2 引数だけを触ればいい。

## 目標指定の回転タイプ

**既定は 5「角度指定なし」**。0（絶対角度）だと着くたびに必ず 0° へ向き直してしまい、
連続でタップして動かすとその場で回る動作が毎回入る。角度を指定しなければ
**進んできた向きのまま止まる**ので、動きが素直になる。

角度指定なし（5 / 6）のときは、着いたときの向きを指示していないことになる。
地図の矢印が嘘をつかないよう、**直前の位置から今の位置への方向**を向きとして採る
（真右なら 0°、真下なら 90°）。前の位置が無ければ、前回の向きをそのまま保つ。

## 到達を絶対座標の観測として使う

**位置IDの通知が一件も来ないキューブがある。** 手元の個体（BLE 2.5.0）がそれで、
電源を入れ直しても、`0x18` を一切書かなくても、iOS でも Android でも 0 件だった。
それでいて目標指定は理由 0 で到達する。つまり**キューブはマットを読めていて、
通知だけが出ていない**。

目標指定（0x03）は座標へ追い込む閉ループ制御なので、**到達したということは
指定座標に居るということ**。これを絶対座標の観測として使う。

- `motorTarget` / `motorMultiTarget` を送るとき、狙った座標を `cube.lastTarget` に覚える
  （複数目標のときは最後の 1 点。そこに着けば全部を通ったことになる）
- `motorResponse` の理由が **0 のときだけ**、その座標を位置IDと同じ扱いで地図と軌跡に載せる
- 理由が 0 以外（タイムアウト、toio ID missed）なら座標は動かさない
- 読み取りの実績に **到達 N** を足して出す

位置IDが来る個体では今までどおり通知が使われ、この経路は単に追加の観測点になる。

失うのは「手で滑らせたときに追従する」ことだけで、地図・軌跡・タップして移動は成立する。

一度も読めていないときの案内も、**到達したことがあるかどうかで文面を変える**。
到達しているなら印刷の話をしても筋違いなので、「通知だけが出ていない」と出す。

### 地図の描き分け

- **緑の破線** … これから向かう目標。目標指定を送ってから応答が返るまでのあいだだけ出る。
  タップし直せば引き直される（`cube.targetPending` と `cube.lastTarget` を見ている）
- **青い線** … 到達して確定した軌跡
- **矢印** … キューブの位置と向き。位置IDが読めているときは濃く、
  到達で確定した最後の位置を出しているだけのときは**薄く**する。
  以前は `cube.onMat && cube.position` を条件にしていたので、位置IDが来ない個体では
  矢印が一度も出なかった

## マットから外れたときの復帰

**外れたら戻る**（既定でオン、位置IDモードのみ）にしておくと、位置IDが読めなくなった
ときに警告音（効果音の「Mat out」）を鳴らしながら、ゆっくりマットへ戻ろうとする。
外れている間は座標が分からないので、**出る直前の座標と向きだけを頼りにした相対操作**になる。

1. まず 1.4 秒、速度 20 でまっすぐ後退する。マットの縁を踏み越えて出ることがほとんどなので、
   たいていはこれで戻る
2. それでも戻らなければ、出た地点から見たマットの中心の方角へ向き直してから、速度 20 で前進する。
   回った量は推測航法の積算値で追う（自分で出している指示なので追える）
3. 位置IDが読めた時点で停止する。12 秒たっても戻らなければ諦めて止まる
4. スティックを触る・停止ボタンを押すと解除される。自動移動中や手動操作中は始まらない

## 推測航法（マットなしで軌跡を見る）

**既定はこちら**。マットが無くても位置を積算して軌跡を描く。あくまで推定なので、
滑り・空転・加減速のぶんだけ実際とはずれていく。マットがあるときは「軌跡の元」を
*位置ID* に変えると実測値になる。

- 単位は mm。角度は位置IDと同じ向き（x が右、y が下、0° が +x 方向で時計回り）。
  ただし**地図の表示だけ 90 度回して**、角度 0（＝リセット直後の向き）が画面の上に来るようにしている。
  上端に「0°」と書いてある側がそれ。読み出しの推定角度は回していない生の値
- **リセット（原点・0°）** で現在地を (0, 0)・角度 0 に戻し、軌跡も消す。
  本体の設定とミニマップの `⟲` のどちらからでも実行できる
- 差動二輪として積分する。`v = (vl + vr) / 2`、`ω = (vl − vr) / 輪距`
  （画面は y が下向きなので、左が速いほど時計回りになる）
- **向きの求め方**は 2 通り。既定は *自動*。
  - *自動（姿勢角があれば使う）*: キューブの IMU が返すヨー角をそのまま向きに使う。滑っても向きはずれない。
    推測航法に切り替えた時点で姿勢角の通知（設定コマンド 0x1D）を有効にする。
    ファームウェアが 2.3.0 未満などで通知が来ない場合は、自動でモーター推定に落ちる
  - *モーターから推定のみ*: 上の式で積分する。滑ると合わなくなる。**回り方が足りないときは輪距を小さく**する
    （回転量は輪距だけで決まり、速度係数には影響されない）
- いま**どちらで向きを出しているか**は、地図とミニマップの左下に「向き: ヨー」「向き: モーター推定」として
  常に描いている。取り違えると回転量が合わない原因になるため
- ヨーの符号（どちら回りで増えるか）は仕様から読み取れないので、**旋回の指示とヨーの変化を突き合わせて
  自動判定**する。手動で「そのまま／反転」に固定することもできる。±180 のまたぎは差分を取って繋ぐ
- もとにする速度は、こちらが指示した値。**モーターの速度情報の取得**（設定パネル）を
  有効にすると、キューブが返す実測値のほうを使う。ただし通知には向きが入っていないので、
  直前に指示した向きを流用している
- 合わない場合は **速度係数**（速度指示値 → mm/s、既定 1.0）と **輪距**（既定 27mm）で調整する。
  toio の速度指示値と実速度の対応は公称値が無いので、既定値は当たりを付けただけの値
- 時間指定モーター制御は、指定時間が過ぎたら速度 0 として扱う。目標指定・加速度指定は
  指示値を追えないため、速度情報の取得を有効にしないと積算されない

## ジョイスティック

モーターのパネルは既定でこのタブが開く。**2本（ラジコン方式）** と **1本**（既定）を
ラジオボタンで切り替えられる。感度などの設定は共通。

- 2本モード: 左が前後、右が旋回。**2本を同時に操作できる**（別々の pointerId を
  持つので、指 2 本でも破綻しない）。各スティックは担当する軸だけを見るので、
  左を横に振っても旋回はしない
- 1本モード: 1本で前後と旋回を兼ねる。円の外に出したら縁に貼りつく
- モードを切り替えるときは両方のスティックを中央に戻して停止させる
  （切り替えた瞬間に走り続けるのを防ぐため）
- `左 = 前後 + 旋回`, `右 = 前後 − 旋回` で混ぜ、どちらかが上限 115 を超える場合は
  **比を保ったまま**縮める（片側だけ頭打ちにすると曲がり方が変わるため）
- **後退時は舵を反転**（既定でオン）。ラジコンで下がるときと同じで、後退中に舵を右に切ると
  車体は左に回る。前後が 0 のその場旋回では反転しない
- 調整できるもの
  - **前後の感度 / 旋回の感度**: 目一杯倒したときの出力（10–115 / 0–115、既定は 100 / 35）
  - **反応カーブ**: 0% で倒し量に比例。上げるほど中央付近が緩やかになり、
    細かい操作がしやすくなる（`(1−e)·t + e·t³`）
  - **不感帯**: 中央の遊び。外側は 0〜1 に伸ばし直してからカーブをかけるので、
    不感帯を広げても最大出力は変わらない
- 混ぜた結果が 1〜7 になったときは 8 まで持ち上げる。キューブの速度指示値は
  **0 か 8〜115** で、1〜7 を送っても動かないため（そのままだと無反応の帯ができる）
- 離すと中央に戻る（「離しても速度を保つ」で巡航にもできる）
- 送信は 50ms 間隔にまとめ、値が変わったときだけ書き込む。
  指の動きのたびに書くと BLE が詰まる
- 掴んだままタブを切り替えたり、ウィンドウからフォーカスが外れた場合は停止する

## スマホでの扱い

Android Chrome での操作を前提に調整してある。

- ダブルタップ拡大の抑止は三段構えにしてある。`touch-action` は継承しないので
  全要素に `manipulation` を指定し、それを尊重しないブラウザ向けに viewport で
  `user-scalable=no, maximum-scale=1` を指定し、さらにそれも無視される場合
  （拡大を強制許可する設定など）に備えて、2 回目のタップの既定動作を JS で潰している。
  最後の保険から除外しているのは、クリックで動く UI（`button` / `input` / `select` /
  `textarea` / `a` / `.cube-tab`）だけ。`touchend` の既定動作を潰すと合成される click が
  飛ばなくなるため。鍵盤は pointerdown/up で鳴らしていて click に依存しないので除外しない
  ——除外すると、ダブルタップで鍵盤が勝手に横スクロールする（拡大が無効なときの
  ブラウザの代替動作）。なお、この結果としてピンチズームも効かなくなる
- 見出しやボタンは `user-select: none`。ログ・入力欄・センサーの値は選択してコピーできる
- マットの canvas は `touch-action` を塞いでいないので、指でなぞればページがスクロールする。
  そのぶん「タップで移動」は pointerdown ではなく、**ほとんど動かずに離したとき**だけ発火する
- 鍵盤は指が入る幅（白鍵 46px）で全音域を並べ、横スクロールで辿る。初期位置は C5。
  スクロール操作として認識されるとブラウザが `pointercancel` を投げてくるので、
  それを拾って発音を止めている
- 入力欄は 16px 未満にしない（iOS 系ブラウザがフォーカス時に勝手に拡大するため）

## 実装メモ

- **`style.css` / `app.js` / 共有ファイルを変更したら、`index.html` の `?v=` を必ず上げる。**
  GitHub Pages はアセットにキャッシュを効かせるので、新しい HTML と古い CSS の
  組み合わせになるとレイアウトが壊れる（実際にスティックが表示されない事故を起こした）
- `../shared/toio.js` … BLE ラッパー。キャラクタリスティックのバイト列組み立てと受信データの
  解釈だけを持つ。[リンクコントロール](../link-control/)と共有しているので、
  ここを変えるときは両方のページを確認すること
- 通知の購読は `properties.notify` を**見ずに、まず試す**。このフラグを正しく申告しない
  ブラウザがあり、フラグで飛ばすと「エラーも出ないまま通知だけ来ない」状態になって
  原因が分からなくなる。1 つ失敗しても残りは続け、結果は `cube.notifyStatus` に残して
  「位置IDの受信を診断」の 1 行目に出す
- `../shared/base.css` … 色・ボタン・パネルなど、`/toio/` 配下で共通の土台。
  浮かせるパネル（`.minimap` の枠・つまみ・半透明の切り替え）もここにあり、
  リンクコントロールの「姿勢のミニ表示」と共有している。
  中身（`#miniCanvas` などの並べ方）だけがこのページの `style.css` にある
- `style.css` … このページ固有の見た目（マット・ジョイスティック・鍵盤・ミニマップなど）。
  `base.css` の後ろで読み込む
- `app.js` … UI。`toio.js` に依存するが逆方向の依存はない
- 書き込みは **キューブごとに 1 本のキューへ直列化** している。BLE は GATT 操作を並行させると
  `operation already in progress` で落ちるため。スライダーのように連続して値が変わるものは
  同じキーの未送信要求を上書きして、キューが詰まらないようにしている
- 姿勢角の「高精度オイラー角」(形式3) は Int16 を 0.01 度として扱っている。
  生の値も `attitude.rawRoll` などに保持しているので、換算が違っていた場合はそこから拾える
