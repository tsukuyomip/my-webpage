# 🎮 toio コントロールパネル (`/toio/control/`)

Web Bluetooth API を直接使って、**toio コアキューブの BLE 機能をひととおり** 操作・観測するための
コントロールパネル。ライブラリ非依存・ビルド不要の素の HTML/CSS/JS で、GitHub Pages にそのまま置ける。

## なぜ自前実装か

ブラウザから toio を触るライブラリとしては `p5.toio` があるが、
姿勢角検出・磁力検出・連続点灯シナリオ・音量指定・再生停止・加速度指定モーター制御・
各種しきい値設定などが未実装または固定値で、「toio にできること全部」には届かない。
このツールは公式の
[BLE 通信仕様](https://toio.github.io/toio-spec/)
にあるキャラクタリスティックを直接叩いている。

## できること

## 動作条件

- **Chrome / Edge / Opera**（Windows・macOS・Linux・ChromeOS・Android）。Safari と Firefox は Web Bluetooth 非対応
- **iOS / iPadOS** は標準 Safari では動かない。Bluefy などの Web Bluetooth 対応ブラウザアプリが必要
- **HTTPS または localhost** から開くこと（GitHub Pages はそのまま条件を満たす）
- 接続は必ずユーザー操作（ボタン押下）から始まる仕様のため、自動接続はできない

## toio 側の制約（ツールの問題ではないもの）

- **押している長さで鳴らす仕組みは無い**。BLE 仕様にあるのは「長さを指定して鳴らす」だけなので、
  鍵盤では最長 2550ms を繰り返し 255 回ぶん予約しておき、離したときに停止コマンド(0x01)で止めている。
  10 分以上押しっぱなしにすると理屈のうえでは音が切れるが、実用上は問題にならない
- **同時発音はできない**。キューブは 1 音しか鳴らせないので、鍵盤は押した順を覚えておき、
  いちばん最後に押した音を鳴らす（last-note priority）。鳴っていない指を離しても何も起きず、
  鳴っている音を離したときだけ、まだ押されている音に戻すか停止する
- **音は半音単位**。スピーカーは MIDI ノート番号 0〜128（128 は無音）と効果音11種のみで、
  周波数を Hz で指定する・波形を送るといったことは BLE 仕様に存在しない。
  無段階の音が要るなら、キューブをセンサーとして使い Web Audio 側で鳴らすことになる
- **磁気センサー・姿勢角検出は対応ファームウェアが必要**（BLEプロトコルバージョン 2.3.0 以降）。
  古いキューブでは設定を書いても通知が来ない。パネル右上の「BLEプロトコル」欄で確認できる
- 磁力検出を使うには、キューブに磁石が装着されていなくても設定自体は可能だが、
  「磁石の状態」と「磁力」は排他で、どちらか一方しか通知されない

## ミニマップ

読み取りセンサーのパネルの「ミニマップ」から、軌跡を画面に浮かせて表示できる。
操作しながら軌跡を見たいときのためのもので、パネル本体と同じ内容（位置ID／推測航法の
どちらでも）を、目盛りやキューブ名を省いて小さく描く。

- 掴んでドラッグすれば好きな位置に置ける。画面外には出ないよう内側に留める
- `⟲` でリセット（原点・北向き）、`⤢` で大きさを 3 段階（130 / 170 / 230px）に切り替え、`✕` で閉じる
- 表示・位置・大きさは localStorage に覚えるので、開き直しても同じ場所に出る
- 本体とミニマップは同じ描画関数を使い、`compact` の有無だけを変えている

## 推測航法（マットなしで軌跡を見る）

「軌跡の元」を **推測航法** にすると、マットが無くてもモーターへの指示から位置を積算して
軌跡を描く。あくまで推定なので、滑り・空転・加減速のぶんだけ実際とはずれていく。

- 単位は mm。角度は位置IDと同じ向き（x が右、y が下、0° が +x 方向で時計回り）。
  ただし**地図の表示だけ 90 度回して**、角度 0（＝リセット直後の向き）が画面の上に来るようにしている。
  「北」と書いてある側がそれ。読み出しの推定角度は回していない生の値
- **リセット（原点・北向き）** で現在地を (0, 0)・角度 0 に戻し、軌跡も消す。
  本体の設定とミニマップの `⟲` のどちらからでも実行できる
- 差動二輪として積分する。`v = (vl + vr) / 2`、`ω = (vl − vr) / 輪距`
  （画面は y が下向きなので、左が速いほど時計回りになる）
- **向きの求め方**は 2 通り選べる。
  - *モーターから推定*: 上の式で積分する。滑ると合わなくなる。**回り方が足りないときは輪距を小さく**する
    （回転量は輪距だけで決まり、速度係数には影響されない）
  - *実機の姿勢角（ヨー）*: キューブの IMU が返すヨー角をそのまま向きに使う。滑っても向きはずれない。
    切り替えると姿勢角の通知（設定コマンド 0x1D）を自動で有効にする。ファームウェアが 2.3.0 以上必要
- ヨーの符号（どちら回りで増えるか）は仕様から読み取れないので、**旋回の指示とヨーの変化を突き合わせて
  自動判定**する。手動で「そのまま／反転」に固定することもできる。±180 のまたぎは差分を取って繋ぐ
- もとにする速度は、こちらが指示した値。**モーターの速度情報の取得**（設定パネル）を
  有効にすると、キューブが返す実測値のほうを使う。ただし通知には向きが入っていないので、
  直前に指示した向きを流用している
- 合わない場合は **速度係数**（速度指示値 → mm/s、既定 1.0）と **輪距**（既定 27mm）で調整する。
  toio の速度指示値と実速度の対応は公称値が無いので、既定値は当たりを付けただけの値
- 時間指定モーター制御は、指定時間が過ぎたら速度 0 として扱う。目標指定・加速度指定は
  指示値を追えないため、速度情報の取得を有効にしないと積算されない

## ジョイスティック

**2本（ラジコン方式）** と **1本** をラジオボタンで切り替えられる。感度などの設定は共通。

- 2本モード: 左が前後、右が旋回。**2本を同時に操作できる**（別々の pointerId を
  持つので、指 2 本でも破綻しない）。各スティックは担当する軸だけを見るので、
  左を横に振っても旋回はしない
- 1本モード: 1本で前後と旋回を兼ねる。円の外に出したら縁に貼りつく
- モードを切り替えるときは両方のスティックを中央に戻して停止させる
  （切り替えた瞬間に走り続けるのを防ぐため）
- `左 = 前後 + 旋回`, `右 = 前後 − 旋回` で混ぜ、どちらかが上限 115 を超える場合は
  **比を保ったまま**縮める（片側だけ頭打ちにすると曲がり方が変わるため）
- **後退時は舵を反転**（既定でオン）。ラジコンで下がるときと同じで、後退中に舵を右に切ると
  車体は左に回る。前後が 0 のその場旋回では反転しない
- 調整できるもの
  - **前後の感度 / 旋回の感度**: 目一杯倒したときの出力（10–115 / 0–115）
  - **反応カーブ**: 0% で倒し量に比例。上げるほど中央付近が緩やかになり、
    細かい操作がしやすくなる（`(1−e)·t + e·t³`）
  - **不感帯**: 中央の遊び。外側は 0〜1 に伸ばし直してからカーブをかけるので、
    不感帯を広げても最大出力は変わらない
- 離すと中央に戻る（「離しても速度を保つ」で巡航にもできる）
- 送信は 50ms 間隔にまとめ、値が変わったときだけ書き込む。
  指の動きのたびに書くと BLE が詰まる
- 掴んだままタブを切り替えたり、ウィンドウからフォーカスが外れた場合は停止する

## スマホでの扱い

Android Chrome での操作を前提に調整してある。

- ダブルタップ拡大の抑止は三段構えにしてある。`touch-action` は継承しないので
  全要素に `manipulation` を指定し、それを尊重しないブラウザ向けに viewport で
  `user-scalable=no, maximum-scale=1` を指定し、さらにそれも無視される場合
  （拡大を強制許可する設定など）に備えて、2 回目のタップの既定動作を JS で潰している。
  最後の保険から除外しているのは、クリックで動く UI（`button` / `input` / `select` /
  `textarea` / `a` / `.cube-tab`）だけ。`touchend` の既定動作を潰すと合成される click が
  飛ばなくなるため。鍵盤は pointerdown/up で鳴らしていて click に依存しないので除外しない
  ——除外すると、ダブルタップで鍵盤が勝手に横スクロールする（拡大が無効なときの
  ブラウザの代替動作）。なお、この結果としてピンチズームも効かなくなる
- 見出しやボタンは `user-select: none`。ログ・入力欄・センサーの値は選択してコピーできる
- マットの canvas は `touch-action` を塞いでいないので、指でなぞればページがスクロールする。
  そのぶん「タップで移動」は pointerdown ではなく、**ほとんど動かずに離したとき**だけ発火する
- 鍵盤は指が入る幅（白鍵 46px）で全音域を並べ、横スクロールで辿る。初期位置は C5。
  スクロール操作として認識されるとブラウザが `pointercancel` を投げてくるので、
  それを拾って発音を止めている
- 入力欄は 16px 未満にしない（iOS 系ブラウザがフォーカス時に勝手に拡大するため）

## 実装メモ

- **`style.css` / `app.js` / `toio.js` を変更したら、`index.html` の `?v=` を必ず上げる。**
  GitHub Pages はアセットにキャッシュを効かせるので、新しい HTML と古い CSS の
  組み合わせになるとレイアウトが壊れる（実際にスティックが表示されない事故を起こした）
- `toio.js` … BLE ラッパー。キャラクタリスティックのバイト列組み立てと受信データの解釈だけを持つ
- `app.js` … UI。`toio.js` に依存するが逆方向の依存はない
- 書き込みは **キューブごとに 1 本のキューへ直列化** している。BLE は GATT 操作を並行させると
  `operation already in progress` で落ちるため。スライダーのように連続して値が変わるものは
  同じキーの未送信要求を上書きして、キューが詰まらないようにしている
- 姿勢角の「高精度オイラー角」(形式3) は Int16 を 0.01 度として扱っている。
  生の値も `attitude.rawRoll` などに保持しているので、換算が違っていた場合はそこから拾える
