# 🎮 toio コントロールパネル (`/toio/control/`)

Web Bluetooth API を直接使って、**toio コアキューブの BLE 機能をひととおり** 操作・観測するための
コントロールパネル。ライブラリ非依存・ビルド不要の素の HTML/CSS/JS で、GitHub Pages にそのまま置ける。

## なぜ自前実装か

ブラウザから toio を触るライブラリとしては `p5.toio` があるが、
姿勢角検出・磁力検出・連続点灯シナリオ・音量指定・再生停止・加速度指定モーター制御・
各種しきい値設定などが未実装または固定値で、「toio にできること全部」には届かない。
このツールは公式の
[BLE 通信仕様](https://toio.github.io/toio-spec/)
にあるキャラクタリスティックを直接叩いている。

## できること

| 分類 | 対応内容 |
|---|---|
| 接続 | 複数キューブの同時接続、送信先の切り替え（選択中のみ / 全キューブ） |
| 読み取りセンサー | 位置ID・標準ID・それぞれの missed、マット上の位置と向きを可視化、軌跡表示 |
| モーター | 基本制御(0x01) / 時間指定(0x02) / 目標指定(0x03) / 複数目標(0x04、最大29点) / 加速度指定(0x05)、速度情報(0xE0)の受信、目標指定の応答デコード |
| 操作系 | ジョイスティック（連続操作）、十字キー、左右モーターのスライダー、キーボード運転（WASD・矢印・Space で停止）、マットをタップして目標指定 |
| ランプ | 消灯(0x01) / 点灯(0x03) / 連続点灯シナリオ(0x04、最大29ステップ・繰り返し指定) |
| サウンド | 再生停止(0x01) / 効果音11種(0x02) / MIDI(0x03、最大59音・音量・繰り返し)、鍵盤で単音再生（オクターブ切り替え可） |
| センサー | 水平検出・衝突・ダブルタップ・姿勢(6面)・シェイクレベル、磁石の状態、磁力（強さ＋向きベクトル）、姿勢角（オイラー角 / クォータニオン / 高精度オイラー角）の可視化 |
| その他 | ボタン、バッテリー残量、BLEプロトコルバージョン |
| 設定 | 水平検出しきい値 / 衝突検出しきい値 / ダブルタップ間隔 / ID通知設定 / ID missed感度 / 磁気センサー設定 / モーター速度情報の取得 / 姿勢角検出設定 |
| デバッグ | 任意のバイト列を任意のキャラクタリスティックへ送信・読み出し、送受信ログ（16進＋デコード結果） |

## 動作条件

- **Chrome / Edge / Opera**（Windows・macOS・Linux・ChromeOS・Android）。Safari と Firefox は Web Bluetooth 非対応
- **iOS / iPadOS** は標準 Safari では動かない。Bluefy などの Web Bluetooth 対応ブラウザアプリが必要
- **HTTPS または localhost** から開くこと（GitHub Pages はそのまま条件を満たす）
- 接続は必ずユーザー操作（ボタン押下）から始まる仕様のため、自動接続はできない

## toio 側の制約（ツールの問題ではないもの）

- **音は半音単位**。スピーカーは MIDI ノート番号 0〜128（128 は無音）と効果音11種のみで、
  周波数を Hz で指定する・波形を送るといったことは BLE 仕様に存在しない。
  無段階の音が要るなら、キューブをセンサーとして使い Web Audio 側で鳴らすことになる
- **磁気センサー・姿勢角検出は対応ファームウェアが必要**（BLEプロトコルバージョン 2.3.0 以降）。
  古いキューブでは設定を書いても通知が来ない。パネル右上の「BLEプロトコル」欄で確認できる
- 磁力検出を使うには、キューブに磁石が装着されていなくても設定自体は可能だが、
  「磁石の状態」と「磁力」は排他で、どちらか一方しか通知されない

## ジョイスティック

倒した方向と量から左右のモーター速度を作る、連続操作のモード。

- 前後 → 並進、左右 → 旋回。`左 = 前後 + 旋回`, `右 = 前後 − 旋回` で混ぜ、
  どちらかが上限 115 を超える場合は**比を保ったまま**縮める（片側だけ頭打ちにすると曲がり方が変わるため）
- 中心から 12% 以内は不感帯。離すと停止（「離しても速度を保つ」で巡航にもできる）
- 送信は 50ms 間隔にまとめ、値が変わったときだけ書き込む。
  指の動きのたびに書くと BLE が詰まる
- 掴んだままタブを切り替えたり、ウィンドウからフォーカスが外れた場合は停止する

## スマホでの扱い

Android Chrome での操作を前提に調整してある。

- ダブルタップ拡大の抑止は三段構えにしてある。`touch-action` は継承しないので
  全要素に `manipulation` を指定し、それを尊重しないブラウザ向けに viewport で
  `user-scalable=no, maximum-scale=1` を指定し、さらにそれも無視される場合
  （拡大を強制許可する設定など）に備えて、2 回目のタップの既定動作を JS で潰している。
  最後の保険はボタン・入力欄・鍵盤などを除外してあるので、連打は殺さない。
  なお、この結果としてピンチズームも効かなくなる
- 見出しやボタンは `user-select: none`。ログ・入力欄・センサーの値は選択してコピーできる
- マットの canvas は `touch-action` を塞いでいないので、指でなぞればページがスクロールする。
  そのぶん「タップで移動」は pointerdown ではなく、**ほとんど動かずに離したとき**だけ発火する
- 鍵盤は 1 オクターブぶんだけ表示し、`◀ ▶` でオクターブを移動する。
  2 オクターブ並べると鍵が細くなりすぎて指で押せない
- 入力欄は 16px 未満にしない（iOS 系ブラウザがフォーカス時に勝手に拡大するため）

## 実装メモ

- `toio.js` … BLE ラッパー。キャラクタリスティックのバイト列組み立てと受信データの解釈だけを持つ
- `app.js` … UI。`toio.js` に依存するが逆方向の依存はない
- 書き込みは **キューブごとに 1 本のキューへ直列化** している。BLE は GATT 操作を並行させると
  `operation already in progress` で落ちるため。スライダーのように連続して値が変わるものは
  同じキーの未送信要求を上書きして、キューが詰まらないようにしている
- 姿勢角の「高精度オイラー角」(形式3) は Int16 を 0.01 度として扱っている。
  生の値も `attitude.rawRoll` などに保持しているので、換算が違っていた場合はそこから拾える
