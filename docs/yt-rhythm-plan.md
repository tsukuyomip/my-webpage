# 🎯 YT Rhythm — 開発プラン

## コンテキスト（なにを作るか）

YouTube の動画を背景に、画面上の指定座標をタップして遊ぶ osu! 系の音ゲー。
**プレイモード**（譜面を読み込んで遊ぶ）と **クリエイトモード**（譜面を作って書き出す）を持つ。

## 決定事項

| 項目 | 採用 | 理由 |
|---|---|---|
| **対象端末** | スマホ優先（タッチ） | 実際に遊ぶのは手持ち端末。PC はマウスで同じ操作が通る。 |
| **MVP のノーツ** | tap のみ | まず判定・エディタ・譜面 I/O を一周させる。hold / drag は次段階。 |
| **譜面の保存** | JSON ファイルの書き出し / 読み込み | 端末に依らず持ち運べる。編集中の内容だけは保険で端末内に自動保存。 |
| **スタック** | Vite + TypeScript（素の DOM + Canvas） | 60fps の描画は結局 Canvas 直描き。UI も軽いのでフレームワーク不要。 |
| **配置** | サブパス `/yt-rhythm/` | 既存アプリと同じ流儀で共存。 |

## アーキテクチャの肝

3 層を重ねる。

```
[ YouTube IFrame Player ]  背景。音と映像。pointer-events: none
[ Canvas オーバーレイ    ]  ノーツ・エフェクト・HUD を 60fps で描画
[ 入力キャプチャ         ]  Canvas がポインタを全部受ける（iframe には渡さない）
```

- **時刻**: `getCurrentTime()` は粗いので、値が変わった瞬間をアンカーにして
  `performance.now()` で外挿する補間クロックを唯一の基準にする。ズレは徐々に吸収。
- **座標**: 動画表示領域を 0..1 に正規化して保存。端末サイズに依存しない。
- **オフセット**: 端末ごとの音ズレを吸収する判定オフセットを設定に持つ。
  判定時刻 = 動画時刻 − (譜面オフセット + 端末オフセット)。エディタもプレイも同じ基準。
- **波形が使えない**: iframe は cross-origin なので音声解析は不可能。
  波形の代わりに BPM ビートグリッド + 再生しながらの打ち込み + 後からの微調整で合わせる。

## 実装フェーズ

### Phase 0 — 足場 ✅
`/yt-rhythm/` に Vite + TS、Pages のビルド／配信、トップページへの導線。

### Phase 1 — プレイヤー基盤 ✅
IFrame API ラッパ、補間クロック、ステージ（動画 + キャンバス + 入力）、判定オフセット設定。

### Phase 2 — プレイモード ✅
tap ノーツの判定（PERFECT/GREAT/GOOD/MISS）、コンボ・スコア・精度、ヒットエフェクト、
判定ズレの可視化バー、一時停止、リザルト。

### Phase 3 — クリエイトモード ✅
配置・選択・移動・削除、時刻の数値／ドラッグ微調整、タイムライン、
BPM スナップ、Undo/Redo、JSON 書き出し・読み込み、試遊、編集内容の自動保存。

### Phase 3.5 — 効果音と広告対応 ✅
判定ごとの効果音（波形を合成。音声ファイルは持たない）、ヒットエフェクトの強化、
コンボ節目の演出、エディタの打ち込み音。
広告は消せないので、流れているあいだはゲームを止めて待ち、終わったら自動で再開する。

### Phase 4 — ノーツ種別の拡張（今後）
hold（長押し）、drag（なぞり）。`Note` のユニオンと描画・判定に分岐を足す。
譜面フォーマットは未知種別を読み飛ばす作りなので後方互換は保てる。

### Phase 5 — エフェクト拡張（今後）
`registerEffect()` に足すだけで増える。譜面側は `note.fx` で指定。
スキン、判定演出、背景演出などをここに載せる。
