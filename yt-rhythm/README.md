# 🎯 YT Rhythm

YouTube の動画の上にノーツを置いて遊ぶタップ音ゲー。
譜面はブラウザ上で作れて、JSON ファイルとして書き出し・読み込みできる。

- **プレイモード**: 譜面 JSON を読み込んで遊ぶ。判定は PERFECT / GREAT / GOOD / MISS。
  判定ごとの効果音とヒットエフェクト、25 コンボごとの演出つき。
- **クリエイトモード**: 動画を指定してノーツを配置・移動・削除し、タイミングを微調整して書き出す。

ノーツは **タップ / フリック（はじき）/ ホールド（長押し）/ ドラッグ（なぞり）** の 4 種類。
ホールドは「離す瞬間に払う」**ホールドフリック**にもできる。

`/my-webpage/yt-rhythm/` に配信される（GitHub Pages）。

## 開発

```sh
npm install
npm run dev      # 開発サーバ
npm run build    # tsc --noEmit && vite build
npm run test:e2e # 通し確認（開発サーバの起動と後片付けまで込み）
```

依存は Vite と TypeScript だけ。UI は素の DOM、ゲーム描画は Canvas 2D。

## テスト

`e2e/run.mjs` が唯一のテスト。**偽の YouTube プレイヤー**を `addInitScript` で
先に生やし、`loadYouTubeApi()` を即 resolve させて全機能を通しで動かす
（サンドボックスから youtube.com へは出られず、実際の再生は検証できないため）。

判定・広告・マルチタッチ・譜面の入出力・打ち込みのジェスチャまで、
実際の DOM とキャンバスを触って確認する。

- **Playwright はグローバル導入のものを使う**。`package.json` に依存を足さない方針なので、
  無ければ `npm i -g playwright`（ブラウザは `/opt/pw-browsers` にあるものを探す）
- `BASE=http://.../` を渡すと、動いているサーバに当てる。渡さなければ自分で
  開発サーバを起動して最後に止める
- 検証の勘どころ: 暗さはキャンバスの画素を読む（`getImageData(4,4,1,1).data[3]/255`）、
  効果音は `AudioBufferSourceNode.prototype.start` を包んで数える、
  書き出しは `waitForEvent('download')`、複数の指は CDP の
  `Input.dispatchTouchEvent` で送る
- **手元で再現しない端末の癖は、ブラウザ API を壊して模す**。たとえば
  「2 本目以降の `setPointerCapture` が例外を投げる」を `addInitScript` で
  差し込むと、押さえながらのタップが落ちる不具合をここで再現できる
- `pkill -f vite` は**自分のシェルごと落とす**ので使わないこと。
  このスクリプトは起動した子プロセスだけを止める

## 譜面フォーマット (formatVersion 1)

```jsonc
{
  "formatVersion": 1,
  "meta": {
    "title": "曲名",
    "videoId": "dQw4w9WgXcQ",
    "author": "作った人",       // 任意
    "difficulty": "Normal"      // 任意
  },
  "timing": {
    "offsetMs": 0,              // 判定時刻 = 動画時刻 - offsetMs
    "bpm": 120,                 // 任意。エディタのスナップ用
    "beatOffsetMs": 0,          // 任意
    "division": 2               // 任意。1=4分, 2=8分, 4=16分
  },
  "display": {                  // プレイ時の見た目・音の初期値
    "dimOpacity": 0.5,          // 動画にかける黒の濃さ (0〜0.85)
    "approachMs": 800,          // ノーツが出てから判定までの長さ (400〜2400)
    "sfxKit": "impact"          // 判定音のセット ("impact" / "tambourine")
  },
  "notes": [
    { "id": "n1", "type": "tap", "time": 12.345, "x": 0.5, "y": 0.4 },

    // はじき。dx / dy は払う向きの単位ベクトル（右が +x、下が +y）
    { "id": "n4", "type": "flick", "time": 13.0, "x": 0.6, "y": 0.4, "dx": 1, "dy": 0 },

    // 長押し。time に押して time + duration まで押し続ける
    { "id": "n2", "type": "hold", "time": 14.0, "x": 0.3, "y": 0.6, "duration": 1.25 },

    // ホールドフリック。長押しに dx / dy を足すと「離す瞬間に払う」になる
    { "id": "n5", "type": "hold", "time": 15.0, "x": 0.7, "y": 0.6, "duration": 0.8, "dx": 0, "dy": -1 },

    // なぞり。始点 (x, y) から path の点を順に通る。dt は time からの相対秒（昇順）
    { "id": "n3", "type": "drag", "time": 16.0, "x": 0.2, "y": 0.5,
      "path": [ { "dt": 0.4, "x": 0.5, "y": 0.3 }, { "dt": 0.9, "x": 0.8, "y": 0.5 } ] }
  ]
}
```

- `time` は秒。`x` / `y` は動画表示領域を 0..1 に正規化した座標なので、画面サイズが変わっても崩れない。
- `hold` / `drag` は **1 ノーツで 2 判定**（押した瞬間 + 最後まで追えたか）。精度と総ノーツ数もその数で数える。
- `duration` / `path` の最後の `dt` は 0.1 秒以上。満たさないノーツは読み飛ばす。
- `fx` を書くとノーツごとにヒットエフェクトを変えられる（現在は `ripple` / `burst`）。
- ホールドフリックを**別種別にせず `hold` の追加フィールドにした**のは、これを知らない
  古いプレイヤーでも**ただの長押しとして遊べる**ため。種別を増やすとノーツごと消えてしまう。
- 読み込み側は知らない `type` やフィールドを読み飛ばすので、将来種別が増えても古い譜面はそのまま読める。
- `display` を持たない古い譜面は既定値（50% / 800ms）で開く。

## 設計メモ

### 時刻の精度

`player.getCurrentTime()` は更新が粗く、そのままでは判定に使えない。
`MediaClock` は「値が変わった瞬間だけをアンカーにして `performance.now()` で外挿し、
ズレは 1 サンプルあたり 15% ずつ吸収する」方式で滑らかな時刻を作る。
0.3 秒以上ずれたらシーク／バッファ復帰とみなしてアンカーを取り直す。

### 判定オフセット

端末やブラウザによって音の遅れが違うので、設定に **判定オフセット** がある。
「遅い」と判定されがちなら + 方向、「早い」なら − 方向。
譜面側の `timing.offsetMs` と合算して使われる。

判定時刻（= 譜面時刻）は常に `動画時刻 - オフセット` で、
エディタの配置・再生・プレイの判定すべてが同じ基準を使う。

### 見た目・音の既定値と上書き

`display` は **譜面が持つ初期値** で、クリエイトモードで決める。
プレイ側はそれをそのまま使うが、設定で「譜面の値を使う」のチェックを外すと
端末側の値で上書きできる（暗い画面が見づらい、この速度は速すぎる、といった調整用）。

暗さはキャンバスに黒を敷いて表現するので、動画の明るさに左右されず一定に効く。
広告の再生中は暗さもノーツも描かない。

判定音のセットも同じ扱いで、曲の雰囲気に合わせて譜面ごとに選べる。

### YouTube アカウントと広告

埋め込みは `www.youtube.com` のプレイヤーなので、**同じブラウザで YouTube に
ログインしていれば、その状態は埋め込みにも引き継がれる**。YouTube Premium なら
広告なしで再生される。

アプリ側からログインさせることはできない（埋め込みプレイヤーにログイン機能はなく、
ログイン済みかどうかを cross-origin で読むこともできない）。できるのは
「YouTube を開いてログインしてもらう」導線を出すところまで。
サードパーティ Cookie をブロックしている環境ではログイン状態が伝わらないので、
その場合は広告を待つ作りがそのまま働く。

### ノーツ種別と判定

`tap` は 1 回の判定。`hold` / `drag` は **始点** と **終端** で 2 回判定する。

- **始点**: どの種別も同じで、始点の位置を判定幅内でタップできたかを見る。
- **終端**: 押し始めてから終わりまでの「追えていた時間の割合」で決める
  （95% 以上 = PERFECT / 80% = GREAT / 50% = GOOD / それ未満 = MISS）。
  終わり際に離したぶんは追い切ったものとして数えるので、短いノーツで損をしない。
- 追えているかの判定は、`hold` は始点から、`drag` は **その時刻に玉がいるべき位置** からの距離で見る。
- 追いかけは **指ごと（pointerId ごと）に独立** しているので、2 本指で別々のホールドを押さえられる。
- 一時停止・バッファ・広告で再生が途切れたら、その時点の割合で終端を確定させる。

`flick` は 1 判定だが、**押した瞬間と払った瞬間で役割が分かれている**。

- **押した瞬間**: ノーツを掴んで、そのときのズレを覚えておく。
  **精度（PERFECT / GREAT / GOOD）はここで決まる**ので、ゆっくり払っても損しない。
- **払い切った瞬間**: 成立するかどうかがここで決まる。押した位置から
  ノーツ半径の 0.55 倍以上、狙った向きから ±0.42π 以内に動かせば成立。
- **離した瞬間**: それでもまだ払えていなければ見逃し。
- 押してから払うまでの猶予は **実時間で 300ms**。譜面時刻で測ってはいけない。
  払うのにかかる時間は指の動く速さで決まるので、0.5 倍速で練習して等速に
  戻した途端に間に合わなくなる、では困る（この点だけホールドやドラッグと逆）。
- 打ち込み側の「これ以上動かしたらドラッグ」より、遊ぶ側の成立距離は甘い。
  作るときは意図して払うが、遊ぶときは忙しいので、ここは意図的に揃えていない。

**ホールドフリック**（`dx` / `dy` を持つ `hold`）は、始点は長押しと同じで、
終端が「払えたか」に変わる。

- 払いを見るのは**終端の判定幅に入ってから**だけ。押さえている最中の指のずれを
  払いと取り違えると、まだ押している途中で勝手に終わってしまう。
- 成立距離は始点からノーツ半径 1 個ぶん（単発のはじきより広い。押さえている指は
  少しずつ動いてしまうため）。`HOLD_SLACK` の内側なので、払っても長押しは切れない。
- 終端の判定は **「追えていた割合」と「払った時刻のズレ」の悪いほう**。
  押さえ切っていても払わなければ見逃し、払えていても途中で見失えば割合が効く。
- 終端を過ぎても判定幅のあいだは払うのを待つ。ちょうどで払えないと取れない、では厳しすぎる。

### 効果音の作り

音声ファイルは持たず、起動時に波形を合成して `AudioBuffer` にする
（再生は buffer を鳴らすだけなので遅延が小さい）。

**明るさは必ずノイズをバンドパスに通して作る。** 持続する正弦波を重ねて
高い音を作ると、倍音比をどうずらしても鉦や鈴のように鳴って間が抜ける。
正弦波は減衰の速い芯（パンチ）にだけ使う。

セットは 2 つあり、設定で選べる。

| セット | 音 |
|---|---|
| ヒット（ビシッ） | 格ゲーの当たり音。0.5ms で立ち上がる芯 + 短い肉 + 下がる芯。余韻を作らない |
| タンバリン（シャン） | 数 ms ずらした粒を重ねて乾いた鈴にする。最初の 1 粒をいちばん強くしないと拍から遅れて聞こえる |

- 判定が良いほど明るく長い。MISS はどちらも低く詰まった音（下降スイープは間が抜ける）
- エディタの打ち込み確認音は別枠の `tick`。余韻があるとノーツが詰まったとき濁る
- 出口に波形整形（tanh）を挟んで、音が重なっても歪まないようにする。
  コンプレッサだと数 ms 遅れるので、音ゲーでは使わない
- 判定音は 0.1 秒ほどで収まるようにしてある。長い余韻は 16 分が続くと滲む

### 種別ごとのシルエット

色を変えるだけでは「何をすればいいか」は伝わらない。**やってほしい動作が
そのまま見た目になる**ように、輪郭から作り分けている。

| 種別 | 狙い | 作り |
|---|---|---|
| タップ | 触って弾けさせたい | 細い輪、ガラスのハイライト、ふちが明るい膜。判定直前に張り詰めて震える |
| フリック | 払いたい | タップと同じ質感に、**払う向きの矢印**を本体の外まで伸ばす。判定が近いほど前にせり出す |
| ホールド / ドラッグ | 長く押していたくなる | 太い輪、内側に落ち込む陰影（押し込める窪み）、溜める溝が最初から見えている。押される前はゆっくり息をする |
| ホールドフリック | 押さえて、最後に払いたい | ホールドの作りに払う向きの矢印を重ねる。矢印は**リリース時刻**に向かってせり出す（はじきは判定時刻に向かってせり出す） |

ホールドとドラッグは同じ「長く触るもの」なので、頭の作りを揃えている。

**長いノーツの接近予兆は細い輪にしない。** 細い輪だとタップと見分けが
つかないので、**半径を時間軸にした帯**を描く。中心に近いほど手前の時刻で、
`半径 = r * (1 + 1.8 * 残り時間 / approachMs)` で時刻を半径に写す。

- **内側の境界** = 押し始める時刻
- **外側の境界** = 離す時刻
- その間だけをハレーション（半径方向のグラデ）で塗る

つまり「ハレーション全体のうち、押している区間だけを切り出したマスク」に
見える。**境界そのものはグラデにせず、はっきりした線で描く**。押し始めは
タップと同じように境界が縮んで迫ってきて（違いは輪の外にハレーションが
付いていること）、押している間は逆に、離す時刻の境界が縮んで迫ってくる。
どちらの瞬間もぼやけないので、叩く／離すタイミングを線一本で読める。
帯の太さがそのまま押さえる時間になるため、短いホールドと長いホールドは
見た瞬間に区別できる。

### タイミングの予告

ノーツは「いつ叩くか」を 3 つの手がかりで見せる。細い輪ひとつだと、
遠いノーツも近いノーツも同じ強さで目に入って読みにくい。

- **縮んでくる接近リング**: 透過度を 40% → 90% に連続で上げる。
  遠いものは薄く、近いものははっきり見える
- **中心から満ちる面**: 縁の内側が中心から広がり、満ちきった瞬間が判定時刻。
  細い輪より面のほうが残り時間を読み取りやすい。濃さも 40% → 80% に上げる
- **種別の色**: タップ=青 / ホールド=紫 / なぞり=緑

なぞりは **どこを通るか** と **いつ通るか** を別々の要素で出す。

- **実線**: 経路そのもの。太さは時間の情報を持たないので常に固定
- **予告帯**: 半透明の帯。**点ごとに「その点を通る番がどれだけ近いか」で
  太さを決める**ので、太い部分が経路上を進んでいく。いつ・どこに指が
  あるべきかが形だけで読める。全体を一律に太らせると「あと何秒でノーツが
  来るか」しか分からず、経路のどこにいるべきかは結局読めない
- どこまで先が膨らむかは譜面の `approachMs` に連動する
- 膨らむタイミングは **100ms だけ先行**させる。ちょうど通る時刻に最大だと
  「広がったのを見てから動く」では間に合わない

押す前と押したあとで道の見え方は変えない。変えると読み方が切り替わって
しまう。変わるのは「どこまで残っているか」だけで、**通り過ぎた側は実線も
帯も描かない**。通過しているあいだは玉から火花が散る。

### エフェクト

`registerEffect(name, factory)` に足すだけで増える。譜面の `note.fx` で
ノーツごとに指定できる。現在 `ripple`（既定）/ `burst` / `trail` / `flick` /
`release` / `milestone`。

はじきの演出だけは 360 度に散らさず、**粒も光条もすべて払った向きへ飛ばす**。
全方向に散らすと「払った」感じが出ない。

当たったときは **閃光 → 衝撃波 → 放射する光条 → 判定文字** を重ねる。
衝撃波を白にすると出現時の接近リングと見分けがつかなくなるので、判定色で出す。
光条の数と広がりは **コンボが伸びるほど増える**（`intensity`）。

- **画面の揺れ**: 当たった瞬間に `EffectLayer.shake()` を足し、指数で減衰させる。
  掛けるのは**ノーツとエフェクトだけ**。暗幕を揺らすと端に隙間が出るし、
  HUD を揺らすと数字が読めない。設定のスライダーで 0（なし）にもできる
- **押さえている間**: ホールドは輪のふちから、ドラッグは玉の後ろから粒を撒く。
  押している手応えは、当たった瞬間の演出だけでは出ない
- **エフェクトはノーツの下に敷く**。当たり終えたノーツの演出が、これから
  来るノーツを覆い隠す理由はない
- 同時に生きるエフェクトには上限があり、詰まった譜面でも古いものから捨てる

### 全画面と横向き

プレイ開始（スタートボタン＝ユーザー操作）で全画面にし、可能なら横向きに
固定する。設定で切れる。

全画面に入れないと向きは固定できない仕様なので、順番は「全画面 → 向き」。
iOS Safari は要素の全画面化に対応せず、向きの固定もできない。できない
ときは静かに諦めて、通常の画面でそのまま遊べるようにしてある。
全画面にした要素は背景が透けるので、CSS で自分で敷く。

### 長押しと選択

長押しで文字が選択されたり、コピーの吹き出しが出たりすると操作が奪われる。
`-webkit-touch-callout: none` と `user-select: none` を body とゲーム画面に
掛け、キャンバスでは `selectstart` / `contextmenu` / `dblclick` も止める。

### 音が止まる

ブラウザは裏に回ると AudioContext を止める。戻ってきても自動では再開しない
ので、そのままだと効果音が鳴らなくなる。`visibilitychange` / `pageshow` /
`focus` で起こし直し、鳴らす直前にも状態を見て止まっていれば再開する
（連呼しないよう間隔を空ける）。

### 複数の指

判定は **pointerId ごとに独立** している。押さえたまま別の指でタップできるし、
2 本指で別々のホールドも押さえられる。

入力を受けるキャンバスには `touch-action: none` を敷き、ページ側も
`overflow: hidden` と `overscroll-behavior: none` でブラウザのジェスチャに
持っていかれないようにしている。

**`setPointerCapture` はマウスとペンにだけ使い、タッチには使わない。**
タッチは最初に触れた要素へ自動で届く（暗黙の捕捉）ので不要なうえ、端末に
よっては 2 本目以降で例外を投げる。その例外が捕捉より後ろの処理を巻き込んで
落とすため、「押さえながらタップすると 2 本目が無視される」という形で出る。
捕捉は失敗してもよいものとして扱う。

### 拡張ポイント

- **ノーツ種別**: `core/types.ts` の `Note` にユニオンを足し、`core/note.ts` に
  長さ・位置の取り方を足したうえで、`render/renderer.ts` の描画と `modes/play.ts` の
  判定に分岐を足す。読み込み側は既に未知種別を無視する作りになっている。
- **エフェクト**: `render/effects.ts` の `registerEffect(name, factory)` に足すだけ。
  譜面の `note.fx` で指定できる。

### 広告

埋め込みプレイヤーの広告は **アプリ側からは消せない**（そういうことはしていない）。
広告を見ないで遊ぶ手段は視聴者側にしかないので、案内だけ出している。

- **Brave ブラウザ**を推奨。既定で広告なしで再生でき、いちばん快適に遊べる
- **YouTube Premium** にログイン済みのブラウザでも広告は出ない

案内は折りたたみの中だと読まれないので、ホームと譜面選びの両方に開いたまま出す。
どちらも使わない場合のために、**広告のあいだはゲームを止めて待ち、
終わったら少し巻き戻して自動で再開する**。

広告かどうかは `getDuration()` が本編の長さと食い違うことで見分ける
（埋め込みプレイヤーは広告の有無を API で教えてくれない）。
広告中はキャンバスの描画と入力を止め、プレイヤー側を操作できるようにするので、
「広告をスキップ」も押せる。

## クリエイトモードの打ち込み

ツールは **＋ 配置** と **↖ 選択** の 2 つだけ。種別は選ばず、**押し方で決まる**。

**押していた時間**と**動かした距離**の 2 つで 4 種類に分かれる。

| | 動かさない | ノーツ半径 1 個ぶん以上動かす |
|---|---|---|
| **0.25 秒未満** | タップ | **フリック**（払った向きを持つ） |
| **0.25 秒以上** | ホールド（押していた実時間が長さ） | ドラッグ（指の軌跡と速さが経路） |

**ホールドフリック**は「長く押して、最後だけ払う」。ドラッグと同じ枠に入るので、
見分けるのは動いた量ではなく **始点から離れていた時間**にしている。
0.25 秒より長く離れていればドラッグ、それ以内なら払い。長さは**始点を離れた時刻**
（離した時刻ではない）。そこが離すべき瞬間で、プレイ側が払いを検出するのも
同じ距離を越えた瞬間だから、作った長さとプレイの手応えが一致する。

「離れていた時間」は通過点からは読めない。**指が止まっているあいだ `pointermove` は
飛んでこない**ので、記録された点だけを見ると「600ms 押さえてから払った」が
「最初からゆっくり動いていた」と区別できない。毎フレーム「最後に分かった指の位置が
始点のそばか」を数えることで、止まっていた時間もちゃんと数えている。

遊ぶときのフリック成立距離は、作るときより甘くしてある（半径の 0.55 倍）。
作るときは意図して払うが、遊ぶときは忙しい。

押しているあいだ、いまどれになっているかがステージとインスペクタにそのまま出る
（0.25 秒を越えた瞬間に紫のホールドへ、動かし始めると緑のドラッグへ変わる。
最後だけ払えばホールドフリックに戻る）。
動画を止めたままでも描けるので、拍に合わせて置いてから長さを直す流れが使える。
判定は離した瞬間に確定し、1 回の打ち込みが Undo 1 件になる。

長さは **再生中なら譜面時刻、停止中なら実時間**で数える。0.5 倍速で
ゆっくり描いても、曲に対する長さは見たとおりになる。なぞりの通過点は
上限に達すると 1 つおきに間引いて間隔を倍にするので、何秒なぞっても
記録は止まらず、点の数だけが一定に保たれる。

しきい値は `src/modes/edit.ts` の `TAP_MAX_SEC` と `DRAG_MOVE_RADII` の 2 つ。

長さはあとから変えられる。タイムラインで **終端の棒を横にドラッグ**するか、
選択中に出る「長さ」の数値・±100 ボタンを使う（なぞりは通過点の間隔ごと伸縮する）。
選択ツールではノーツを掴んで移動でき、なぞりは形を保ったまま動く。選択中は
通過点のハンドルが出るので、1 点ずつ位置を直せる。

## 制約

- 埋め込み再生が許可されていない動画、年齢制限つきの動画は再生できない。
- 広告そのものはアプリ側から消せない（Brave / Premium を案内し、それ以外は待つ）。
- iframe は cross-origin なので音声波形は取得できない。エディタは波形の代わりに
  BPM のビートグリッドと「再生しながら置く」ワークフローで合わせる。
- モバイルは初回再生にユーザー操作が必要（スタートボタンがそれを兼ねている）。
